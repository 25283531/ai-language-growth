## 1. 结论、目标与边界

### 1.1 审查结论

现有“课本词表 → 自动补全课程”链路**结构可用，内容不可用**：

- 能生成 `schemaVersion 2` 课程 JSON，能按单元写 `curriculum_drafts`，单测通过。
- 但音标/释义只覆盖预置课程的 210 个词；未命中词典时中文栏会写入英文（如“这是orange。”）；例句是模板句（如“This is a weather.”）；音节切分错误（`elephant → ["el","ep"]`）。
- 例句中文和句型在草稿阶段被丢弃（`toDraftContent()` 只保留英文例句，不保留 `patterns`）。
- 发布链路**不写 `vocabulary_items`**，运行时只读该表；自动补全的音标/释义/例句**进不了课堂**。
- 没有“课文”这一层资源：没有句子数组、逐句翻译、语法点、双速音频字段；`reading_story` 只是一个活动类型。
- 发布必须先人工 `submit → approve`，与“生成即可用、使用中直接改”的目标冲突。
- 预置课程每级 30 词、共 210 词，只能做演示骨架，无法支撑七阶段教学目标。

### 1.2 本任务书目标

1. **按单元录入课文**，生成完整教学资源：整篇/逐句领读（正常 + 慢速）、逐句翻译、语法点、重点词、理解题、跟读评测、角色扮演等。
2. **取消人工审核门禁**：生成后自动校验并直接可用；管理员随时查看、编辑、回滚、下架，不需要先审核才能发布。
3. **纠正七阶段模型**：七个阶段是**按能力维度独立发展的教学路径**，不是全局关卡；CEFR 只作外部参考，不作为解锁条件。
4. **建立 3,000–5,000 词规模的词汇库**，教材单元词自动纳入；不再以“每级 30 词”作为课程容量。
5. **补齐 V1.1 总体设计中的内容生产层**：四层内容结构、学校英语双轨、教材映射、证据事件、慢速拆读、隐私约束。
6. 把上述能力拆成可执行、可验收的开发任务，按阶段交付。

### 1.3 非目标

- 不做教材扫描件 OCR/版权内容抓取；课文由有使用权的管理员录入或上传。
- 不改 ASR/发音评估供应商；复用现有 `/speech/evaluate`。
- 不重做 AI 教师四角色、记忆体系、人格引擎、多模型路由的总体架构；但本任务书生成的资源必须接入这些既有模块，并遵守其契约。
- 不重做家长端视觉；只增加必要的阶段展示与教材映射接口。
- 不做自动掌握判定；掌握仍由证据与既有规则决定。
- ESP32/硬件端不在本任务书范围；若后续做，另立任务书。

### 1.4 与 V1.1 总体设计的关系（硬约束）

本任务书只覆盖 V1.1 的**第 2、3、4、10 章**中与课程内容生产直接相关的部分，但不得违反总体设计的硬约束：

| 约束 | 对本任务书的要求 |
|---|---|
| 教学逻辑与客户端分离 | 课文资源、活动顺序、评估规则全部由后端生成与下发；Android 只渲染，不做教学决策。 |
| 所有模型可替换 | 翻译、语法抽取、活动生成必须走 `ModelRouterImpl` + `AiGatewayService` 的 task route；不得在代码中写死供应商/模型名。 |
| 教学数据必须有可靠证据 | 课文活动必须产出 `learning_evidence`；翻译只作辅助，不产生掌握；AI 不得写掌握状态。 |
| 双轨进度独立 | 语言习得轨与学校英语轨分别映射能力节点，不得用一条轨锁住另一条。 |
| 阶段不是关卡 | 阶段按能力维度独立；不得因某一能力未达标而禁止其他能力。 |
| 儿童隐私 | 录音、文本、学习数据遵循 `consent_records`、最小留存、可查看/删除；课文录入不得包含儿童个人信息。 |
| 内容版本化 | 所有已上线单元必须有版本、内容哈希、审计记录与回滚能力。 |

### 1.5 对 V1.1 第 10 章“审核后发布”的正式修订

V1.1 第 10 章原规则为“正式发布的课程资源必须有版本控制与内容审核”“发音与拼读内容必须人工审核，AI 生成不直接发布”。经产品方 2026-11-17 确认，**该审核后发布规则取消**，本任务书及后续实现一律采用：

```
生成 → 自动校验 → 直接 active → 管理员随时查看/编辑/下架/回滚
```

这不是临时例外，而是对 V1.1 第 10 章的正式修订；已在 `DECISIONS.md` 的 D-022（并同步 D-027）追加修订条款，后续开发以该修订为准，不得再实现“提交审核 / 审核通过才能发布”的旧流程。

配套的质量控制（不是发布门禁）：

- 机器可判定的校验全部前置（结构、空译文、空音标、语音长度、评估规则、能力节点、ID 唯一、敏感内容）。
- 发音/拼读内容增加**专项自动核对**（词典 IPA 对照、音素表校验、TTS 回读一致性抽检）。
- 上线后**运营抽检**（不是发布门禁）：首周对每个新单元抽检重点句/音素；发现问题一键下架并回滚。
- 审计日志完整记录生成、编辑、下架、回滚。
- 管理员必须在同一页面看到“自动质检报告”，而不是“待审核队列”。
- 人工可以随时编辑已上线内容；编辑即时生效，版本可回滚。

> 设计原文“教错一个音比没教危害更大”仍然成立。取消的是人工**前置审批**，不是取消质量控制；自动核对与上线后抽检仍保留。

## 2. 核心设计决策

| 编号 | 决策 | 说明 |
|---|---|---|
| D-1001 | **生成即可用，取消人工审核门禁** | 生成后通过自动校验即进入 `active`；管理员可直接查看/编辑/下架/回滚。 |
| D-1001-A | **正式取消 V1.1 第 10 章“审核后发布”** | 2026-11-17 产品确认；生成后自动校验直接 `active`，人工随时编辑；`DECISIONS.md` D-022 / D-027 已记录修订。 |
| D-1002 | **课文是一等资源** | 新增 `passage`、`sentence`、`grammarPoint` 契约；课文不再塞进单个 `demonstrationText`。 |
| D-1003 | **阶段按能力独立** | 听、说、发音、词汇、语法、交流、学校英语各自计算；某维度低不阻塞其他维度。 |
| D-1004 | **CEFR 与成长阶段解耦** | 产品目标为 Pre-A1 → A1；`pre-A1…C2` 只表示内容难度/外部参考，不是学习者关卡。 |
| D-1005 | **词汇规模 3,000 核心 + 2,000 扩展** | 以词族计 3,000 覆盖日常听说约 95%；5,000 支撑阅读；教材词无条件纳入。 |
| D-1006 | **双速音频按课程身份缓存** | 每句 1.0 与 0.65 两档；键含 `topicId + contentId + contentVersion + sentenceId + speedTier`。 |
| D-1007 | **编辑即时生效、版本可回滚** | 编辑提升 `version` 与 `contentVersion`，下一节课生效；旧版本保留。 |
| D-1008 | **自动校验替代人工门禁** | 结构、内容、语音、评估、节点、安全全部机器检查；不通过拒绝启用。 |
| D-1009 | **词表路径保留但降级** | `textbook/generate` 保留用于快速词表/演示；正式教材走“单元课文”入口。 |
| D-1010 | **210 词只用于冒烟测试** | 预置课程保留为测试/演示数据，不再作为教学容量承诺。 |
| D-1011 | **内容生产四层结构** | 知识层、教学层、素材层、课程层分别建模、分别版本化。 |
| D-1012 | **学校英语双轨生成** | 每个单元同时考虑语言习得轨与学校英语 A–E 模块；进度独立。 |
| D-1013 | **教材映射可配置** | `textbook_mappings` 由后台维护，不把地区教材硬编码进程序。 |
| D-1014 | **慢速拆读到音节/音素** | 重点词支持整词 → 音节 → 音素 → 合成 → 自然语速；屏幕同步高亮。 |
| D-1015 | **理解与表达分开评估** | 听读理解与主动说出分别记证据；翻译不产生掌握证据。 |
| D-1016 | **稳定迁移需跨场景 + 隔天** | 至少两个不同场景独立使用，且隔天无提示仍能使用；内容要提供迁移变体。 |
| D-1017 | **模型分级路由** | L0 规则/缓存、L1 轻量、L2 教学解释、L3 规划；按 task route 调用，不写死模型。 |
| D-1018 | **不复制受限第三方代码** | 只采用 ECDICT（MIT）数据；其他项目仅借设计/模式，许可证未清前不碰代码。 |

## 4. 内容生产四层模型与双轨体系

### 4.1 四层模型（V1.1 第 10 章落地）

| 层 | 内容 | 本任务书落点 | 生产与校验 |
|---|---|---|---|
| 知识层 | 单词、音素、句型、语法 | `lexicon_entries`、`phoneme_items`、`sentence_patterns`、`grammarPoints` | 结构化知识库 + ECDICT + 人工可编辑；机器校验 IPA/音素/句型 |
| 教学层 | 教学步骤、示范、练习活动 | `activities`、`teacherUtteranceZh`、`demonstrationText`、scaffolds | AI 辅助生成；自动校验评估规则；可编辑 |
| 素材层 | 图片、音频、动画、故事 | `media_assets`、句子/单词音频、可选图片 | 合法授权素材 + TTS；记录 license/attribution；双速缓存 |
| 课程层 | 顺序、目标、评估条件 | `curriculum_units`、`objectives`、`stageHint`、`assessment` | 教研制定框架；生成器组装；版本化 |

每个生成资源必须带：

```json
{
  "layer": "knowledge|teaching|material|course",
  "source": "ecdict|llm|tts|editorial|textbook",
  "license": "MIT|provider-terms|original|licensed-textbook",
  "version": "contentVersion"
}
```

### 4.2 学校英语双轨（V1.1 第 3 章）

同一单元同时产出两条轨的资源，**进度独立**：

| 模块 | 内容 | 本任务书生成的资源 |
|---|---|---|
| A 字母认知 | 26 字母、大小写、字母名称与常见发音 | 字母卡、字母音音频、大小写配对活动 |

| D 拼写与书写 | 字母书写、单词拼写、简单句书写 | 拼写活动、句子补全、书写提示 |

示例（Apple，来自 V1.1）：

| 语言习得主线 | 学校英语主线 |
|---|---|
| 听懂 Apple、看图理解苹果 | 认识字母 A、P、L、E 与单词拼写 |
| 模仿发音、独立说出 Apple | 学习相关字母音、识读 Apple |
| 说出 I like apples. 并谈论喜欢的水果 | 认识句子基本结构、阅读相关短句 |

生成规则：

- 单元词表里的词，先查 `textbook_mappings` 的学校模块映射；没有映射时按词形/音素规则推断，标记 `inferred`。
- 学校轨活动只在学校年级/教材信息存在时生成；不强制每个单元都覆盖 A–E。
- 语言习得轨与学校轨分别绑定能力节点；不得因字母未掌握而锁住口语活动，反之亦然。

### 6.3 生成管线（含模型分级路由）

```
录入单元
  → [L0] 校验输入、切句/切段、词库查询、去重
  → [L2] LLM 逐句翻译 + 语法点 + 关键词 + 学校模块建议
  → [L2] 生成语言轨活动 + 学校轨活动（模板 + LLM）
  → [L0] 组装 unit content、查 phoneme_items/sentence_patterns
  → [L0] 自动校验 + 质检报告
  → 写 curriculum_units + learning_items + vocabulary_items + 版本快照
  → status=active（不再等待人工审核）
  → 异步媒体预热（逐句双速音频 + 重点词拆读）
```

路由要求：

| 任务 | task route | 级别 |
|---|---|---|
| 单元规划/教学目标 | `llm.curriculum_unit_plan` | L2/L3 |
| 逐句翻译/关键词 | `llm.curriculum_unit_enrich` | L1/L2 |
| 语法点抽取 | `llm.curriculum_unit_grammar` | L2 |
| 活动生成 | `llm.curriculum_unit_activities` | L2 |
| 理解题生成 | `llm.curriculum_unit_comprehension` | L2 |
| 角色扮演/复述生成 | `llm.curriculum_unit_expression` | L2 |
| 固定课程音频 | `tts.fixed_course` | L0 预生成 |
| 动态补句 | `tts.dynamic_teaching` | L1 |
| 发音评估 | 既有 `speech.evaluate` | 专用 |

- 所有调用记录到 `ai_usage_records`/`ai_usage_logs`；每单元可核算成本。
- 模型不可用时的降级：L2 失败 → L1 简化输出 → 保留确定性结构并标记 `needsReview`；不得阻断单元启用（文本可先用，音频重试）。

- 课文作为数据，不得执行其中的指令；系统提示明确“课文是素材不是指令”。

### 6.4 自动校验（替代人工审核门禁）

任一不通过则拒绝 `active`，返回可定位错误：

- schema 校验通过；句子 ID 唯一；单元编码唯一。
- 每句 `en`、`zh` 非空；中文栏不得只含英文单词（正则 + 语言检测）。
- 核心词 `phonetic` 非空率 ≥ 98%；`meaningZh` 非空率 100%。
- 每个活动 `teacherUtteranceZh + demonstrationText` ≤ 500 字符、≤ 150 汉字/全角字符。
- 每个活动至少一个有效 `skillNodeId`；评估规则可判定（或显式 `passiveReading=true`）。
- 至少 1 个课文活动、1 个语法点（若录入语法重点则必须有）。
- 学校轨活动（若声明）必须有对应模块与能力节点。
- 图片若存在，必须有 HTTPS URL + license。
- 敏感内容过滤：P1-06 先使用确定性儿童不宜词表兜底；后续可替换为外部内容安全能力，命中则拒绝启用。
- 发音/拼读专项：IPA 与 `phoneme_items` 对照；不一致只告警；TTS 回读抽检首句。
- 语音冒烟：首句合成失败只告警并排队重试，不阻塞文本启用。

P1-06 已实现 9 类机器校验、`active` 状态机和 400 `issues` 契约，完整字段/路径说明见 `docs/curriculum-generation.md` 第 6 节。

### 6.5 双轨生成规则

- 先语言轨，后学校轨；学校轨不得复用语言轨的“已掌握”状态。
- 学校轨活动按教材年级选择模块：低年级优先 A/B，中年级 C/D，高年级 E。
- 每个模块至少 1 个活动；没有足够素材时标记 `notGenerated`，不硬造。
- 双轨活动共享同一课文语境，但评估节点不同。
- 生成结果中明确 `track: 'language' | 'school'`。

### 7.2 慢速拆读（V1.1 阶段 2 差异化能力）

- 目标词先查 `phoneme_items` 与音节切分；生成：
  1. 整词慢速（0.65）
  2. 音节逐个（0.65，必要时 0.55）
  3. 困难音素单独（0.65/0.55）
  4. 音节合成
  5. 恢复自然语速（1.0）
- 屏幕同步高亮当前发音单位；客户端按音频时间轴或分片索引高亮。
- 只对 `focusWords`（2–4 个/单元，含困难音素或课文重点）生成拆读，控制 TTS 成本。
- 发音评估返回错误音节/音素时，只练错误部分，不要求整词盲目重读。
- 耐心规则：原型阈值 85 分（正式阈值须儿童样本校准）；未达标先降级拆分/换例词/换示范，最多陪练 5 轮；不催促、不跳过。
- 语音一致性：同一老师音色、同口音、同音节发音；切换 TTS 模型前做音色接近度检查。

### 7.3 证据与掌握（V1.1 第 4 章）

每个活动必须声明 `evidenceKind`：

| evidenceKind | 说明 | 可产生的掌握证据 |
|---|---|---|
| `listening_comprehension` | 听懂、选图/选词/判断 | 听力/被动词汇 |
| `reading_comprehension` | 读懂短句/故事 | 阅读理解 |
| `production` | 主动说出/造句/对话 | 口语/主动词汇/语法 |
| `pronunciation` | 跟读/音素评估 | 发音 |
| `transfer` | 新场景使用旧知识 | 迁移 |
| `none` | 翻译、讲解、被动听读 | 不产生掌握 |

硬规则：

- 理解与表达**分开记**；不能因为听懂了就标记会说。
- 翻译只作辅助，`evidenceKind='none'`，不产生掌握。
- “稳定迁移”至少：两个不同场景独立使用 + 隔天无提示仍能使用；内容必须提供至少两个场景变体。
- AI 不得写掌握状态；只写证据，状态由规则计算。
- 复习调度沿用间隔重复 + 主动提取；课文句子/词可进入复习队列。

## 8. 发布、编辑与版本

### 8.1 新状态机

```
(生成) → active（自动校验通过，直接可用）
active → disabled（管理员下架，保留内容与版本）
disabled → active（重新启用）
active/disabled → archived（归档）
```

- 不再要求 `under_review` / `approved`。
- 旧 `submit/approve/reject` 接口标记 `deprecated`，保留一个版本兼容，不再被发布链路调用。

### 8.2 编辑已上线内容

`PUT /api/v1/admin/curriculum/units/{unitId}/content`

- 请求体：完整 `textbookUnitContent` + `expectedVersion`。
- 事务内：校验 → 写 `curriculum_unit_versions` 快照 → 更新 `curriculum_units.content`、`contentVersion=sha256(content)`、`version+1` → 同步更新 `learning_items.content` → 异步重建语音。
- 乐观锁：`expectedVersion` 不匹配返回 409。
- 句子 ID 稳定；修改句子文本时保留 ID，音频键随 `contentVersion` 变化。
- 编辑立即对下一节课生效；当前正在上的课可继续使用旧内容。
- 编辑学校轨/语言轨任一轨，不影响另一轨的独立进度。

### 8.3 回滚、下架、审计

- `POST /units/{unitId}/rollback` `{ version }`：复制历史快照为新版本，重算 `contentVersion`，同步学习项。
- `POST /units/{unitId}/disable`：`availability=disabled`，运行时不再下发。
- `POST /units/{unitId}/enable`：重新启用。
- 所有操作写审计：操作者、时间、版本、变更摘要、原因。
- 自动质检报告随版本保存，便于回看“当时为什么判过”。

### 8.4 缓存与语音

- 运行时 `contentVersion` 已由 `sha256(JSON.stringify(content))` 计算；编辑后自然失效。
- TTS 缓存键：`topicId + contentId + contentVersion + sentenceId + speedTier`。
- 重复播放命中缓存，不重复计费（对应 V1.1 验收第 1 项）。
- 编辑句子后旧音频保留（回滚可用），新音频异步生成；失败按需合成兜底。
- 禁止按纯文本哈希跨课程复用（D-014）。

## 9. 词汇库建设（3,000–5,000）

### 9.1 为什么 210 词不够

- 七阶段目标包含“听懂日常指令、十个主题词汇、两词组合/简单句、八个场景双向交流、自主日常交流”，是**理解 + 主动产出**目标。
- 常用阈值：约 3,000 个词族覆盖日常口语约 95%；4,000–5,000 个词族才能较好覆盖一般阅读。
- 3,000 仍不足以覆盖教材 + 兴趣 + 生活全部场景，因此采用 **3,000 核心 + 2,000 扩展**，并让教材词无条件进入。
- 210 词只够冒烟测试和演示，不能作为课程容量承诺。

### 9.2 可用的数据基础（已核实）

`G:\workbuddy\英语\ecdict.csv`（ECDICT，MIT）：

- 770,611 条词条。
- 218,065 条有音标；770,238 条有中文释义。
- 42,231 条有 `frq` 词频，45,443 条有 `bnc` 词频。
- 按词频取前 3,000：音标 2,979 条（99.3%）、中文 3,000 条（100%）。
- 前 5,000：音标 4,949 条（99.0%）、中文 5,000 条（100%）。
- 标签可用：`zk` 1,603、`gk` 3,677、`cet4` 3,849、`cet6` 5,407 等。
- `exchange` 字段可用于归并词形变化，按词族统计。

**结论：3,000–5,000 词库不需要模型逐词编造；AI 只补例句、搭配和儿童化改写。**

### 9.3 建库规则

1. 取 `frq` 前 3,000 为 `core`；`frq` 3,001–5,000 + `bnc` 补充为 `extension`。
2. 用 `exchange` 归并规则变化，统计“词族”；展示仍用词条。
3. 排除：专有名词、缩写、成人/暴力/歧视词、纯感叹词；功能词单列 `function_words`，不做词卡但计入句子覆盖。
4. 每个核心词必须有：IPA、词性、中文释义、儿童安全例句 + 中文、主题领域、词频序号、来源/许可证。
5. 一词多义只保留儿童常用义项；多义项用 `senses[]` 扩展，不在本期做全义项。
6. 教材单元词无条件加入：即使超出 5,000，也以 `source='textbook'` 入库。
7. 儿童安全审核：释义/例句敏感词过滤；不确定的词标 `childSafe=false`，不进入儿童课程。
8. 与《义务教育英语课程标准（2022 年版）》对齐：教材词、课标词优先；词频表作为补充，不替代课标。

### 9.4 阶段词汇覆盖目标（累计，不是解锁条件）

| 阶段 | 听/读理解目标 | 主动产出目标 | 说明 |
|---|---|---|---|
| 0 语言启蒙与适应 | 100–150 | 20–50 | 高频问候、指令、物品 |
| 1 听力理解与语言反应 | 500 | 150 | 指令、颜色、数字、身体、动作、情绪 |
| 2 声音辨别与发音形成 | 700 | 300 | 不追求新增词量，重点是听辨/发音 |
| 3 词汇理解与主动表达 | 1,500 | 800 | 十个主题领域 |
| 4 短语与完整句子 | 2,200 | 1,300 | 搭配、句型替换 |
| 5 对话与语言组织 | 3,000 | 2,000 | 八个场景 |
| 6 自主日常交流 | 4,000–5,000 | 3,000 | 生活叙事、自然追问 |

> 这些是内容覆盖目标，用于检查“教材/课程是否给够了词”，**不是孩子必须达到的关卡**。

### 9.5 覆盖率指标

- 每个单元生成后计算：新词数、复用词数、核心词占比、课文 token 覆盖率。
- 目标：阶段 1–3 材料 ≥95% token 覆盖；阶段 4–6 ≥98%。
- 未覆盖词进入“待补词”清单，管理端可一键加入词库。
- 管理端提供“词库覆盖”页：按阶段、主题、教材版本查看缺口。
- 与教材映射联动：单元词优先来自教材词表，其次课标词，再次词频扩展。

## 10. 七阶段模型改造

### 10.1 产品口径（写入文档与 UI 文案）

> CEFR（欧洲语言共同参考框架）是外部参考标准；本产品的七个阶段是**语言能力发展的教学路径**，不是七个必须依次完成、不能回头的关卡。孩子可以在不同能力上处于不同阶段：例如听力已经进入第三阶段，发音可能仍处于第二阶段。系统不得因某一能力未达标就禁止孩子发展其他能力。

### 10.2 七阶段定义

| 阶段 | 名称 | 核心目标 |
|---|---|---|
| 0 | 语言启蒙与适应 | 熟悉英语声音与老师的声音，愿意听、愿意模仿；听懂 Hello、Bye、Yes、No 等高频表达，能按指令做动作、指认图片。不强制完整口语回答，能听懂、能反应就是进步。 |
| 1 | 听力理解与语言反应 | 建立声音与意义的联系：日常指令、物品、颜色、数字、身体部位、常见动作与情绪。理解与主动说出必须独立评估。 |
| 2 | 声音辨别与发音形成 | 三层推进：听辨相似音（如 /ɪ/ 与 /iː/、/s/ 与 /θ/）；模仿发音（整词、音节、困难音、合成、恢复自然语速）；专业语音评估记录稳定音与易错音。 |
| 3 | 词汇理解与主动表达 | 按主题建立有类别、有场景的词汇体系（自我与家庭、食物、动物、学校、家居、动作、情绪等十个领域）。 |
| 4 | 短语与完整句子 | 从单词到两词组合、短语、主谓结构、简单句，再到喜好、否定与疑问表达；重点是理解结构并学会替换内容，而非背诵句型。 |
| 5 | 对话与语言组织 | 围绕自我介绍、家庭、学校、食物、购物、天气、兴趣、日常生活八个场景进行双向交流；孩子答不上来时老师降难度搭梯子，而不是机械追问。 |
| 6 | 自主日常交流 | 摆脱预设问答：谈当天发生的事、听孩子讲简单经历、自然追问、理解不完整的句子并帮其补成正确表达，适时纠错但不打断每一次交流。 |

### 10.3 与 CEFR 的关系

- 产品目标：6–9 岁零基础，Pre-A1 起点，A1 为第一阶段综合能力参照；按每天约 15 分钟估算，零基础到 A1 约 12–18 个月。
- 七阶段是内部教学路径；CEFR 是外部参照。粗略对应（仅参考，不是门槛）：
  - 阶段 0–1：Pre-A1
  - 阶段 2–3：Pre-A1 → A1 过渡
  - 阶段 4–5：A1
  - 阶段 6：A1 → A2 发展
- 现有 `C2` 预置数据是历史/超建内容，不作为本产品目标；UI 不应展示“七级 CEFR”或“总等级”。
- 教材 `level` 字段保留为内容难度标签；不得作为学习者权限。

### 10.4 数据与算法

- `skill_nodes.growthStage` 表示该**能力节点**所属阶段。
- 增加 `abilityDomain` 派生：`LISTEN → listening`、`PRON → pronunciation`、`VOCAB → vocabulary`、`GRAM → grammar`、`SPEAK → speaking`、`COMM → communication`、`SCHOOL → schoolEnglish`。
- `learner_skill_states` 仍按节点存掌握状态。
- `StageProfileService`：
  - 每个领域取 `masteryCode >= forming` 的最高 `growthStage`；
  - 若没有 forming，取 `encountered` 的最高阶段；
  - 都没有则返回 0；
  - 返回每阶段节点数与证据数，便于解释。
- 阶段只是展示与规划参考，不是访问控制。
- `curriculum_stages` 表保存阶段名称、描述、教学目标，供 UI 与内容标签使用。

### 10.5 Planner 改造

1. **禁止跨领域全局门槛**：活动可排性只由该活动自身能力节点的硬前置决定；不得因“发音阶段低”过滤听力/词汇活动。
2. **候选池按领域补齐**：当前主题候选不足时，从其他领域取可排活动；不得因单一领域全部阻塞而返回 `null`。
3. **自由交流门槛收敛**：`hasIndependentConversationFoundation` 只作用于 `LA.COMM.free_talk` 本身；未达成仍可安排 stage 5 对话练习。
4. **难度带按领域**：保留按活动节点/轨计算；补充按 `abilityDomain` 的测试。
5. **双轨独立**：学校英语轨与语言习得轨分别计算难度与前置，互不锁死。
6. **阶段展示**：rationale 可说明“本课重点领域”，不得出现“未达到阶段 X，禁止学习 Y”。

### 10.6 UI 改造

- 家长端/管理端显示七条能力阶段条（或雷达图），每条独立。
- 文案使用“听力阶段 3 / 发音阶段 2”，不使用“总等级 3”。
- CEFR 只出现在教材/内容标签，如“内容参考 A1”，不显示为学习者等级。
- 课程目录不因阶段锁定；可标注“建议”，但不阻止进入。
- 显示“本单元覆盖的领域”，而不是“本单元解锁等级”。

### 10.7 测试

- 学习者听力 stage 3、发音 stage 0、词汇 stage 3：仍能排到听力/词汇 stage 3 活动。
- 单一领域全部硬前置未达成：planner 从其他领域返回活动，不返回 `null`。
- free_talk 前置未达成：只锁 free_talk，不锁其他交流活动。
- 双轨：字母未掌握不影响口语活动；口语强不自动标记拼写掌握。
- 阶段画像：七领域独立计算，互不影响。

## 14. 隐私、安全与合规

面向 6–9 岁儿童，以下要求从第一版执行：

- **监护人同意**：沿用 `consent_records`；语音处理与 AI 服务使用需监护人授权留痕。
- **录音**：默认不长期保存原始录音，只保存必要的学习结果与结构化评估；提供查看/删除。
- **儿童个人信息**：课文/词库/例句不得包含儿童姓名、学校、地址等个人信息；课程内容与用户数据分离。
- **第三方模型**：不把儿童个人信息传给未授权供应商；优先自托管/合规供应商；记录处理范围与保存期限。
- **教材版权**：录入前确认授权；不提供教材抓取；课文原文的存储/分发范围与授权一致；素材层记录 license/attribution。
- **内容安全**：自动敏感内容过滤；管理员可一键下架；审计可追溯。
- **AI 身份**：AI 老师必须明确自己是 AI，不诱导隐私，不伪装父母/朋友。
- **商业化**：儿童端不得自行购买会员；不设置面向儿童的广告/诱导消费。
- **保留期限**：TTS 文本、质检报告、编辑历史按最小必要保存；可配置清理任务。

### 18.5 staging 验证（上线前）

> 完整、可填写的检查表见 [`docs/deployment/staging-migration-checklist.md`](./deployment/staging-migration-checklist.md)。

生产迁移前必须先在 staging 演练。staging 只用于验证迁移和运行时兼容，**不用于灌种子或跑集成测试**。

1. **与生产同大版本 PostgreSQL**
   - staging 的 PostgreSQL 大版本必须与生产一致（生产为 16.x，就用 16.x），并确认扩展、排序规则、时区和连接参数一致。
   - 本地 PostgreSQL 18.6 的通过结果不能替代同大版本 staging 的验证结论。
2. **独立库与独立账号**
   - 使用独立 database（如 `ai_language_growth_staging`）和独立 role；不复用生产库、生产账号或生产 schema。
   - role 仅授予 staging 库所需权限，不授予生产库权限；`DATABASE_URL` 只注入 staging 环境，不把生产凭据写入脚本、日志或仓库。
3. **先备份，再 `migrate deploy`**
   - 迁移前做全量备份（schema + data），记录当前 migration 版本；实际恢复到临时库验证备份可用，并保留备份与恢复记录。
   - 只执行 `npx prisma migrate deploy`（仓库脚本为 `npm run prisma:migrate`），不要执行 `migrate dev`；迁移前后各跑一次 `prisma migrate status` 并留存输出。
   - 迁移后做只读检查：目标表/列/索引存在、关键行数合理、应用健康检查通过。
4. **禁止 seed 和集成测试**
   - staging 不执行 `npm run prisma:seed`。
   - staging 不执行 `m1-api.integration.test.ts`，也不执行任何会创建用户、学习者、会话、证据或学习记录的写测试。
   - 这些测试只在本地或一次性隔离库执行；staging 需要运行时验证时，使用只读健康检查或专用只读 smoke。
5. **失败处理**
   - 迁移失败不得手工修改 `_prisma_migrations`；优先恢复备份或前向修复，保留完整日志。
   - 生产执行仍需变更审批、维护窗口和回滚方案；staging 通过不等同于生产已批准。

## 19. 风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|

| 教材映射错误 | 内容不对应学校进度 | 映射可编辑、标记来源；缺映射回退；不硬编码 |

### 21.3 术语

- **词条（headword）**：词典中的一个拼写形式。
- **词族（word family）**：原形 + 规则屈折/派生，如 `walk / walks / walked / walking`。
- **阶段（stage）**：能力维度上的发展位置，不是全局等级。
- **CEFR**：欧洲语言共同参考框架，外部参考，不是本产品的关卡系统。
- **active**：内容已通过自动校验并可直接下发；不等于“人工审核通过”。
- **四层**：知识层、教学层、素材层、课程层。
- **双轨**：语言习得轨 + 学校英语轨，进度独立。

### 23.3 课型定义

- **课文型课**：一节课是一个完整闭环——听句子 → 跟读句子 → 重点词发音 → 语法点 → 完形练习达标结课。
- **单词型课**：沿用现有单词学习流程（整词 → 音节 → 音素 → 合起来 → 自然语速 → 跟读评测），不新增页面。

### 23.4 P1：逐句跟读页

- 数据：`PassageSentence` 新增整句音标 `phonetic`（优先生成时写入；缺失时按 `lexicon_entries` 逐词拼接并在 UI 标注“自动拼接”）。
- 客户端：课文页「跟读练习」→ 独立页；每页一句：英文、中文、整句音标；正常/慢速试听；按住跟读复用 `/api/v1/speech/evaluate`；顶部显示 `第 n / N 句`；最后一句完成后自动进入重点词汇页。
- 验收：5 句可前后切换；每句都有评分与反馈；退出后可续读；全部完成自动推进。

### 23.5 P2：重点词汇页

- 数据：`focusWords` 补齐 `pos`（词性）、`syllables`、`difficultPhonemes`、`example`（含中文）。
- 客户端：每词展示音标、中文、词性、音节、难音、例句；正常/慢速整词播放（**不拆音节播放**）；按住跟读评测；全部完成进入语法页。
- 验收：`mother / together / dishes / balcony` 六项信息齐全；两种语速可播；评分可用；完成后自动推进。

### 23.6 P3：语法讲解 + 完形练习

- 数据：新增 `grammar_points`（unitId、知识点、原句、例句列表、讲解稿）与 `grammar_quiz_items`（grammarPointId、题干、选项、答案、解析）。

- 客户端：语法页展示原文句 + 多个例句；「重听讲解」与「开始练习」并排；逐题作答并即时给解析。
