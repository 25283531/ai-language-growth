## 远程联调证据

远程联调地址和操作方式见 [`docs/deployment/remote-services.md`](deployment/remote-services.md)。2026 年 11 月 8 日在 `152.136.230.132` 使用 `alg-postgres`、`alg-redis` 和 `alg-backend` 完成了数据库重建、Prisma 迁移、seed 及 M1 API 冒烟；结果包括 health、TTS 缓存、开课、重复、慢速、提问、幂等重放、结课和成长归档。该结果不替代真实供应商和真实儿童样本验收。

2026 年 11 月 8 日再次检查真机测试后的远程状态：三个容器均健康且未重启；health 与 speech quota status 返回成功。真机基础课堂操作已留下课堂、重复和慢速记录。检查发现服务器原后端版本缺少语音额度迁移，因此已部署当前代码、应用 `20261108050000_speech_quota_ledger` 并重建后端与管理页。远程额度冒烟验证了预留、结算、状态查询、释放，以及无租约音频上传返回 HTTP 400、有效租约上传成功。历史 PostgreSQL 日志包含迁移前缺表及真机测试期间的查询错误；最新 5 分钟后端无错误，数据库/缓存无新错误（其中一条近期 PostgreSQL 语法错误来自本次检查命令转义，不是应用请求）。因此原真机测试不能证明额度门禁，需在更新部署后重新测试 APK 的额度流程。

本次审计后的下一代码节点新增后台任务路由配置，使用现有 `ai_task_routes` 与 `ai_route_rules` 表保存策略；迁移文件为 `20261108170000_m2_editable_route_rules`。

2026 年 11 月 8 日部署该节点时，后端先于数据库迁移启动，短暂因缺少 `ai_task_routes.maxConcurrency` 进入重启循环；应用 `20261108170000_m2_editable_route_rules` 后恢复。随后三次 health 检查均通过且重启次数不再增加，四个容器均健康，迁移状态为最新。该次部署时 `ADMIN_CONFIG_TOKEN` 尚未设置，后台管理 API 返回 503；部署顺序已补入 `docs/deployment/remote-services.md`。

2026 年 11 月 8 日已在服务器 `.env` 配置独立的 `ADMIN_CONFIG_TOKEN` 与 `MODEL_CONFIG_ENCRYPTION_KEY`，重建后端后 health 返回 200、带管理令牌的配置读取返回 200、无令牌请求被拒绝。密钥没有纳入仓库。每日路由预算代码由 GitHub Actions 运行 `42470028074` 验证通过，并部署到服务器；容器健康、重启数为 0，后台读取到 11 条任务路由及预算配置。成本从用量账本按 UTC 日期汇总，按配置等级选择更低级别备选；达到预算或当天存在无法计价的外部调用时，关闭外部路由并使用 L0。并发预留是进程内保护，当前单副本部署有效；启用横向扩容前必须迁移到数据库或 Redis 原子预留。

## 下一里程碑

M2 代码范围已完成，2026 年 11 月 8 日开始 M3 Android 正式客户端。首个切片位于 `apps/android`：Compose 课堂首页连接后端开课接口并渲染服务端指令，客户端强制 HTTPS；APK 由 `.github/workflows/android-client.yml` 云端编译。现有远程联调服务仅提供 HTTP，因此在为服务增加 HTTPS 入口前，该正式客户端不能连接当前远程地址；音频额度流程继续由 M1 原型覆盖。
