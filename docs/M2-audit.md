## 教学 Agent 定义与调用时机

`services/backend/src/agents/agent-contracts.ts` 是可执行契约。Agent 是职责边界，不代表部署多个模型；实际调用仍由 Teacher Orchestrator 通过 Model Router/Gateway 完成。

| 角色 | 何时调用 | 允许做什么 | 明确禁止 |
| --- | --- | --- | --- |
| Teacher Orchestrator | 每个学习者回合 | 读取会话、能力证据、当前指令和额度策略，决定是否评估、是否调用教师模型、写入证据并请求下一活动 | 不把客户端作为教学决策方 |
| Planner | 开课；活动完成后需要下一活动；候选活动多于一项时调序；结课长期关注规划 | 在已发布活动、硬前置、难度和复习门槛内选择目标并给出理由 | 不修改掌握状态，不接受模型自报掌握结论；连续失败时不替代规则方法阶梯 |
| Teacher | 儿童提问或闲聊，需要语言解释的实时回合 | 生成儿童安全话术，使用人格和有限交互偏好 | 不更新能力状态，不决定下一个活动；固定课程指令和换方法由编排器规则生成 |
| Assessment | 任务确实要求 ASR/发音评估，或完成作答后需要结构化观察 | 调用对应语音服务并产出证据 | 普通交流不强制做发音评估；LLM 不能单独晋级能力 |
| Growth Mentor | 每堂课结束；后续阶段报告请求 | 基于已验证证据输出成长解释和下一步建议 | 不宣布“已掌握”，不改能力状态 |
| Memory Manager | 结课后批量执行；监护人查看/整理记忆 | 只提取明确表达的教学偏好，过期清理并审计 | 不把全部对话写成长久记忆，不写学习能力状态 |
| Personality Engine | 结课且证据/偏好发生变化时 | 在白名单内调整每个学习者的教师风格并保存版本历史 | 不修改固定安全人格，不制造情感依赖 |

### 普通交流分流规则

`Teacher Orchestrator` 在收到 `freeUtterance` 后先用 L0 规则判断：

- 含问号、疑问词或“吗/呢”等明显疑问形式：调用 Teacher 的 `llm.simple_dialogue` 提问回应。
- 其他自由发言：调用同一路由的普通闲聊回应。
- 两种回应都只生成短话术并合成语音；当前活动、复习占用、方法阶梯、能力状态和学习证据保持不变。
- 没有 `freeUtterance` 的文本/音频/点选回答仍按当前任务评估。

### Agent 引用时机

Agent 是职责契约，不代表部署多个模型。编排器按以下顺序引用：

1. 每个回合先由 `Teacher Orchestrator` 判断意图、当前活动和额度策略。
2. 普通提问或闲聊只引用 `Teacher` 的 `llm.simple_dialogue`，不引用 `Assessment`，不写能力证据，也不推进当前活动。
3. 只有当前活动有真实作答，且活动配置了 ASR/发音评估或确定性答案规则时，才引用 `Assessment`；普通交流永远不进入评估路由。
4. 评估未完成（`evaluated=false`）时，保留当前活动、复习领取和方法阶梯；缺少配置不能被记为失败。被动听读没有回答时允许活动结束，但不产生能力证据。
5. 活动完成后引用 `Planner` 选择下一个已发布、通过硬前置和难度门槛的候选；连续失败时只由服务端方法阶梯换法，当前活动仍在进行时不调用 Planner，也不使用 `llm.method_adaptation` 修改确定性状态。
6. 没有合格剩余活动时结束本堂课。结课时按顺序执行 `Growth Mentor`、`Memory Manager` 和 `Personality Engine`；重复结课命中归档快照，不重复调用这些 Agent，也不重复计费。

结课接口已做幂等保护：已完成课程再次请求会读取已归档成长快照，不重复调用成长/记忆/人格 Agent，也不重复计费。

### Agent 定义补充

- `Teacher Orchestrator` 是唯一的流程编排者，负责把规则结果组装成可执行回合；它不是一个可由客户端调用来改变能力状态的模型。
- `Planner` 只能在服务端筛选后的候选集中排序，不能创建活动、绕过硬前置、修改掌握状态，也不能把连续失败转换成“已完成”。
- `Teacher` 只处理问题、闲聊和需要语言解释的回应；固定课程指令、纠错换法和语速调整由规则与方法阶梯生成。
- `Assessment` 只输出任务级观察。发音 API、ASR、点选和文字答案分别保留来源；`evaluated=false` 时禁止写学习证据、重算状态和结算复习结果。
- `Growth Mentor`、`Memory Manager`、`Personality Engine` 只在结课或明确的管理动作中调用，输入必须来自已验证记录；它们都不能修改能力状态。
- Agent 是职责契约，不等于部署多个模型。实际模型调用统一通过 Model Router/Gateway；预算熔断或供应商不可用时回到规则和固定课程，不改变上述权限边界。

代码节点按功能分别提交到 GitHub，并以 GitHub Actions 验证；不在本机执行构建或测试。
