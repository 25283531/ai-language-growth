# 发音评估专项：成本、准确性与“不每次上传录音”的边界

> 结论先行：**不做任何上传，就无法得到供应商级的音素评分；端侧/ ASR 置信度只能做粗筛和练习反馈，不能单独作为掌握证据。**
> 可行方向不是“永不上传”，而是“只在需要评分的口语任务上传目标词片段，并优先选择不保留、不训练的供应商”。

## 1. 当前链路与成本事实

### 1.1 链路

```
Android 本地录音（保留供回放）
  → Base64 随课堂回合提交（服务端不落盘）
  → 后端请求内转 data: URI
  → ASR 适配器：音频 → 文本/置信度
  → Pronunciation 适配器：音频 + 目标文本 → 总分 + word/syllable/phoneme 单元
  → 规则引擎：pass/fail + 证据
  → PronunciationCoachService：错误单元 → 文本模型 → 一句纠正 → TTS
```

代码落点：

- `services/backend/src/lessons/lessons.controller.ts`：`audioBase64` → `data:` URI；
- `services/backend/src/orchestrator/orchestrator.service.ts`：`assess()`、`persistedLearnerResponse()`；
- `packages/ai-provider-sdk/src/vendor-pronunciation.ts`：Azure / Speechace / 驰声适配器；
- `packages/ai-provider-sdk/src/http.ts`：`loadAudio()` 支持 `data:`、平台媒体路径、HTTP URL。

### 1.2 计费口径

- 账本：`per_second`（ASR/发音按秒）、`per_call`（按次）、`per_1000_chars`（TTS）。
- 设计快照（仅用于量级，不是供应商报价）：
  - TTS：1000 汉字 ≈ 2.7KB，按 0.05 元/1000 字节 ≈ **0.135 元/课**；
  - ASR：300 秒 × 0.00022 ≈ **0.066 元/课**；
  - 发音：8 次 × 0.01 ≈ **0.08 元/课**；
  - LLM：≈ **0.008 元/课**；
  - 合计 ≈ **0.289 元/课**；1000 课/日 ≈ **289 元/日**。
- TTS 默认日预算 60 元，约 444 课触发熔断（按上述快照）。
- 发音成本占比约 28%，但它是“掌握证据”的关键，不应优先砍掉；应先砍重复上传和无效评分。

### 1.3 现在最容易被忽略的重复成本

1. **同一段音频既送 ASR 又送发音**：两个供应商各收一次；如果发音适配器也做识别，ASR 结果没有被复用。
2. **每个回合都评分**：听说跟读、点选、自由对话都走发音，很多回合根本不需要音素级评分。
3. **长录音整段上传**：孩子说了 15 秒，只考一个单词，却把 15 秒全送评分。
4. **失败重试重复计费**：网关降级链可能在多个供应商间重放；需要幂等/结果缓存（发音结果不能跨孩子复用，但同一请求内可复用）。

## 2. “不上传录音”能不能准确判断发音？

### 2.1 直接回答

| 方案 | 能否判断“发音是否标准” | 准确性 | 适用 |
|---|---|---|---|
| 完整音频送专业发音评估（Azure/Speechace/驰声） | 能，能到音素/音节 | 最高；受麦克风、口音、环境噪声影响 | 掌握证据、正式评估 |
| 只送 ASR，拿文本/置信度 | 只能判断“像不像这个词” | 中低；同音异词、吞音、重音错误会漏 | 理解性任务、粗筛 |
| 端侧特征/模板匹配（MFCC、DTW、轻量模型） | 能判断“像不像示范” | 低到中；对设备/口音/语速敏感，难解释 | 课堂即时反馈、游戏化练习 |
| 不上传、只看是否开口/时长 | 不能 | 无 | 只解决“敢不敢说” |
| 只上传目标词片段（1–3 秒） | 能，接近整段 | 中高；切分边界和协同发音会损失一点 | 单词/短语跟读，推荐 |

**因此：**

- 如果“准确”指音素级、可用于 `mastered` 的证据：**必须把包含目标词的音频交给专业发音评估**；端侧或 ASR 置信度不够。
- 如果“准确”指“孩子这次明显读错了，给个提示”：端侧/ASR 可以覆盖一部分，但会漏掉重音、元音长度、辅音浊化等。
- 不上传并不等于免费：端侧模型、维护、设备兼容、误判带来的教学成本都要算。

### 2.2 差异从哪里来

1. **信息量**：音素评分需要看频谱细节；ASR 只保留“最可能的词”，把发音错误吸收成另一个词或直接纠正。
2. **目标文本对齐**：专业评估做强制对齐，知道哪个音素错；ASR 只给整句文本，无法定位。
3. **评分校准**：供应商用儿童/非母语语料校准；端侧小模型很难覆盖 6–9 岁儿童的声音。
4. **重音/韵律**：很多错误不是音素错，而是重音、节奏、语调；只有带韵律评分的引擎能看见。
5. **环境**：家庭噪声、麦克风差异会放大端侧误判；云端模型通常有降噪/信道补偿。

## 3. 推荐的分层方案（省费用但不牺牲证据）

### 3.1 课堂内：两级评估

**A. 理解性回合（听、点选、跟读模仿但不要求独立发音）**

- 只走 ASR，拿文本/置信度；不调用发音评分。
- 目的：判断“听懂了吗”，不是“音素标准吗”。
- 成本：只付 ASR。

**B. 口语产出回合（目标词/短语）**

- 端侧先做 VAD/端点检测，切出**目标词所在片段**（1–3 秒），而不是整段录音。
- 只把这个片段送发音评估；`targetText` 用当前活动的目标词，不用整句。
- 分数只作为“练习反馈”；是否计入独立掌握，还要看 `prompted` 和场景/跨天规则。
- 成本：按 8 次 × 1.5 秒 ≈ 12 秒/课，比整段 60–120 秒下降 **80–90%**。

**C. 边界情况才升级**

- 分数在阈值附近（如 55–70）或 ASR 与目标词不一致时，才允许重录/整段复核。
- 一次课堂最多 1–2 次升级，避免“越错越贵”。

### 3.2 掌握判定：发音分数只是证据之一

- `passed` 不等于 `mastered`；还要满足独立、场景数、跨天回忆。
- 端侧分数不得直接写 `mastered`；最多生成 `practice` 反馈。
- 发音供应商失败时：本轮标记 `assessment_unavailable`，不伪造通过，也不因技术失败降级；让孩子重试或走文本/点选替代。
- 记录 `providerAlias/modelAlias/score/units/confidence`，便于以后换供应商后回溯。

### 3.3 隐私与供应商选择

- 服务端不落盘；但音频仍会在请求内离开设备到供应商。隐私政策必须写“为当次评估转发给语音服务商”，不能写“完全不上传”。
- 选型硬条件：**不用于模型训练、可配置最短留存、支持儿童语音、支持目标词评分**。
- 如果供应商必须留存：改用“只传目标词片段 + 变声/匿名化不可行时明确告知”，不要假装隐私。
- 端侧方案只在“完全离线/无网”场景作为降级，不作为掌握证据。

## 4. 需要补的实验与验收

| 实验 | 方法 | 通过标准 |
|---|---|---|
| 阈值校准 | 20–30 条儿童录音，人工标注“通过/不通过”，对比供应商分数 | 误判样本可解释；阈值不是拍脑袋 |
| 片段 vs 整段 | 同一批录音，切目标词片段与整段分别评分 | 分数相关性 ≥0.8；单词任务差异可接受 |
| ASR-only 粗筛 | 用 ASR 置信度判断发音 | 只用于练习反馈；不得进入掌握证据 |
| 端侧 fallback | 无网/供应商失败 | 课堂不中断；明确提示“本次未评分” |
| 成本 | 记录每课 ASR 秒数、发音秒数/次数、TTS 千字符 | 单课成本可归因；缓存命中率可观测 |
| 格式 | Android AAC/MP4、WAV、OGG 分别送 Azure/Speechace | 不支持的格式在服务端 415 或转码，不静默失败 |

## 5. 当前实现的已知缺口

1. **没有片段切分**：现在整段 Base64 同时送 ASR 和发音；目标词片段化尚未实现。
2. **格式矩阵未验证**：Azure 适配器只接受 WAV/OGG；Android 当前录 MP4/AAC，若选 Azure 会直接报错。选 Speechace 或加服务端转码。
3. **发音结果没有置信度字段**：不同供应商的分数不可直接比较；换供应商需要重新校准阈值。
4. **没有同请求内复用**：ASR 和发音各加载一次音频；网络与供应商调用是两次。
5. **端侧评分未实现**：当前“不上传”只有“不落盘”，不是“不出设备”。

## 6. 建议的下一步（按顺序）

1. 选一个支持儿童语音、目标词评分、可关闭留存的供应商；确认音频格式。
2. 在 Android 加 VAD/目标词片段导出（先固定 1.5 秒窗口），只对口语任务上传片段。
3. 后端加 `PronunciationPolicy`：任务类型 → 是否评分、送整段还是片段、阈值、升级次数。
4. 用真实录音校准阈值；把结果写进 `docs/` 与测试夹具。
5. 再评估端侧模型；只有达到“练习反馈”准确率才上线，且永不单独写 `mastered`。
