# 本地数据库与词库导入

> 更新时间：2026-11-18  
> 适用范围：本机开发、迁移和集成测试。**不要把这套命令指向生产数据库。**  
> 本地实例：PostgreSQL 18.6，端口 `15433`，仅监听 `127.0.0.1`，`trust` 认证（无密码）。

## 0. 前置约定

以下命令默认在仓库根目录执行：

```powershell
cd G:\workbuddy\英语\ai-language-growth
```

每个新开的 PowerShell 窗口都要重新设置 `DATABASE_URL`：

```powershell
$env:DATABASE_URL='postgresql://postgres@127.0.0.1:15433/ai_language_growth?schema=public'
```

本地数据目录为 `G:\pgdata15433`，PostgreSQL 便携二进制在 `G:\pg18\bin`。  
该数据目录没有把端口写进 `postgresql.conf`，所以启动时必须用 `-o` 显式指定 `15433`；不要只执行 `pg_ctl start`，否则可能落到默认的 `5432`。

## 1. 启动 PostgreSQL（15433）

先检查是否已经在运行：

```powershell
& G:\pg18\bin\pg_ctl.exe -D G:\pgdata15433 status
```

如果没有运行，启动：

```powershell
& G:\pg18\bin\pg_ctl.exe -D G:\pgdata15433 `
  -l G:\pgdata15433.log `
  -o "-p 15433 -c listen_addresses=127.0.0.1" `
  start
```

确认端口可用：

```powershell
Test-NetConnection 127.0.0.1 -Port 15433
```

预期 `TcpTestSucceeded : True`。日志在 `G:\pgdata15433.log`。

> 当前工作区已经初始化好 `G:\pgdata15433` 和数据库 `ai_language_growth`，日常启动只需上面的 `pg_ctl start`。  
> `G:\pg18` 便携包只有 `initdb`、`pg_ctl`、`postgres`，没有 `psql` / `createdb`；不要对已有数据目录重复执行 `initdb`。如果数据目录被删掉，需要重新准备 PostgreSQL 客户端或重新初始化数据目录。

## 2. 应用 Prisma 迁移

```powershell
$env:DATABASE_URL='postgresql://postgres@127.0.0.1:15433/ai_language_growth?schema=public'
npm run prisma:migrate
```

该命令实际执行的是 `prisma migrate deploy`，只应用仓库中已有的迁移，不会生成新的迁移。

迁移后建议重新生成 Prisma Client：

```powershell
npm run prisma:generate
```

检查迁移状态：

```powershell
npx prisma migrate status --schema services/backend/prisma/schema.prisma
```

预期：

```text
24 migrations found in prisma/migrations
Database schema is up to date!
```

> 迁移数量会随仓库演进变化，以命令实际输出为准。

迁移单独保证场景外键目标。执行只读校验：

```powershell
npm run check:scenario-baseline
```

预期：

```text
[scenario-baseline] OK：8/8，含 story_scene。
```

该检查不写库；`story_scene` 缺失时，完形通过证据会因 `learning_evidence.scenario` 外键失败。CI 在 `migrate` 之后、`seed` 之前执行同一检查。

## 3. 导入 ECDICT 词库

词库 JSON 默认位于：

```text
packages/vocabulary/data/lexicon.json
```

先做不写库的校验：

```powershell
npm run lexicon:import:dry
```

确认无误后导入：

```powershell
npm run lexicon:import
```

预期输出包含：

```text
import file: ...\packages\vocabulary\data\lexicon.json: families=5000 core=3000
imported lexicon entries: 5000
textbook words: linked=... added=...
```

说明：

- 导入采用 `upsert`，按 `word` 幂等，可以重复执行。
- 默认会读取现有 `curriculum_drafts.wordList` 和 `textbook_units.metadata`，把教材词也纳入词库；已有词只补空字段，不覆盖教材提供的音标/释义。
- 只导入全局词库、不处理教材词：

  ```powershell
  npm run lexicon:import:global
  ```

- 需要从 ECDICT CSV 重新生成 `lexicon.json` 时：

  ```powershell
  npm run lexicon:build
  npm run lexicon:coverage
  npm run lexicon:import
  ```

  默认读取仓库上级目录的 `G:\workbuddy\英语\ecdict.csv`；可用 `ECDICT_PATH` 指向其他 CSV。`lexicon:coverage` 只读生成 `docs/lexicon-coverage.md` 与 `packages/vocabulary/data/lexicon-coverage.json`，不写数据库。

### 空库时的执行顺序

如果数据库是全新的，先执行 `lexicon:import` 再执行 `prisma:seed`，导入时还没有教材草稿/教材单元，`textbook words: linked=0 added=0` 是正常的。

需要教材词关联时，在 `prisma:seed` 之后**再执行一次**：

```powershell
npm run lexicon:import
```

导入是幂等的，不会重复插入。

## 5. 启动测试后端（3100）

集成测试默认访问 `http://127.0.0.1:3100/api/v1`，因此需要先启动后端。

### 终端 A：构建并启动

在仓库根目录：

```powershell

cd services\backend

$env:DATABASE_URL='postgresql://postgres@127.0.0.1:15433/ai_language_growth?schema=public'
$env:PORT='3100'
$env:AI_GATEWAY_MODE='mock'

```

`npm start` 执行的是 `node dist/main.js`，会一直占用终端。

> **不要用 `npx tsx src/main.ts` 启动测试后端。**  
> 本仓库用 `tsx` 直接运行 Nest 时，`ImageCacheService` 的构造参数元数据会缺失，出现 `Cannot read properties of undefined (reading 'startImageCache')`。这是启动方式问题，请使用编译后的 `npm start`。

## 6. 停止

### 停止后端

在终端 A 按 `Ctrl+C`。如果是后台启动的进程，先找 PID 再停止：

```powershell
Get-NetTCPConnection -LocalPort 3100 -State Listen |
  Select-Object LocalAddress, LocalPort, OwningProcess

Stop-Process -Id <PID>
```

### 停止 PostgreSQL

先确认后端已停止，再执行：

```powershell
& G:\pg18\bin\pg_ctl.exe -D G:\pgdata15433 stop -m fast
```

再次检查：

```powershell
& G:\pg18\bin\pg_ctl.exe -D G:\pgdata15433 status
Test-NetConnection 127.0.0.1 -Port 15433
```

预期状态为 `no server running`，端口连接失败。

## 7. 常见问题

### 端口 15433 被占用

```powershell
Get-NetTCPConnection -LocalPort 15433 -State Listen
```

如果是旧的 `postgres` 进程，先确认数据目录，再停止；不要直接杀其他项目的数据库进程。

### `Environment variable not found: DATABASE_URL`

当前 PowerShell 窗口没有设置环境变量。重新执行：

```powershell
$env:DATABASE_URL='postgresql://postgres@127.0.0.1:15433/ai_language_growth?schema=public'
```

### 集成测试返回 `课程活动不存在: act-greet-repeat-hello`

没有执行种子脚本：

```powershell
npm run prisma:seed
```

### 集成测试第一次返回 `ECONNREFUSED 127.0.0.1:3100`

后端没有启动，或没有监听 `3100`。先完成“终端 A”，确认：

```powershell
Test-NetConnection 127.0.0.1 -Port 3100
```

### 不要使用生产库

`prisma:migrate`、`lexicon:import`、`prisma:seed` 和 `m1-api.integration.test.ts` 都会写数据库。生产库只允许在备份、变更审批和维护窗口下执行正式迁移，禁止在生产库上跑 seed 或集成测试。

需要验证生产网络或版本时，只能使用独立 staging 环境，并遵守以下规则：

1. **与生产同大版本 PostgreSQL**：staging 的 PostgreSQL 大版本必须与生产一致（生产为 16.x 就用 16.x），并确认扩展、排序规则、时区和连接参数一致。本地 PostgreSQL 18.6 的通过结果不能替代同大版本 staging 的验证结论。
2. **独立库与独立账号**：使用独立 database（如 `ai_language_growth_staging`）和独立 role；不复用生产库、生产账号或生产 schema。role 只授予 staging 库所需权限，不授予生产库权限。
3. **先备份，再 `migrate deploy`**：迁移前做全量备份（schema + data），记录当前 migration 版本，并实际恢复到临时库确认备份可用。只执行 `npx prisma migrate deploy`（仓库脚本为 `npm run prisma:migrate`），不要执行 `migrate dev`；迁移前后各跑一次 `prisma migrate status` 并留存输出。
4. **禁止 seed 和集成测试**：staging 不执行 `npm run prisma:seed`，也不执行 `m1-api.integration.test.ts` 或任何会创建用户、学习者、会话、证据、学习记录的写测试。这些测试只放在本地或一次性隔离库；staging 只做迁移检查、只读健康检查或专用只读 smoke。
5. **失败处理**：迁移失败不得手工修改 `_prisma_migrations`；优先恢复备份或前向修复，并保留日志。生产执行仍需变更审批、维护窗口和回滚方案。

详细规则见任务书 v1.1 第 18.5 节。
