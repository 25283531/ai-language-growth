# M0 / M1 交付核查

核查依据：《AI Language Growth Platform V1.1 总体设计与开发任务书》第 8、9、11 章，仓库内 M1 QA / live API 报告、源码、数据库 schema 与 GitHub Actions 工作流。状态以当前仓库可复查的代码或工作流证据为准；报告中的旧结论不自动视为当前验收证据。

## 结论

- **M0 设计资料已形成，但基线冻结没有完成。** 任务书列出的教学体系与总体架构可在 PDF 中找到；不过 M0/M1 接口契约文档只有简短索引，统一决策仍标注为待确认草稿，而且任务书明确要求 M1 开始前锁定体系、数据库、模块与接口，仓库记录显示这一关没有正式关闭。
- **M1 原型代码已交付，但阶段验收未完成。** M1 QA 报告给出的结论是“有条件通过”。当前仓库还有明确的 M1 功能缺口，部分原验收脚本不在仓库中，也没有由当前 GitHub Actions 重跑。
- 因此不能把 README 中的 “M0 delivered / M1 complete” 当作阶段验收通过。先关闭 M0 基线与 M1 可代码修复项，再继续扩展 M2。

## 修复顺序

1. 冻结 M0：补齐并核验接口/数据字典，确认统一决议状态，记录版本与验收清单。
2. 修复 M1 可代码交付缺口：Android 动态开课和音频上传；集成 GitHub 工作流重跑真实五动作与八项硬指标；补能力理解/表达隔离及难度渐进逻辑。
3. 安全与隐私发布门槛：监护人身份、单独授权、授权撤回、访问控制和删除链路。没有完成前只保留为受控原型。
4. 外部验收单独排期：真实儿童样本、模型质量/阈值、真实延迟和账单价格。
5. 以上有代码证据的基础项通过后，再继续剩余 M2 路由、语音分级、预算及记忆能力。

本核查过程没有在本机执行测试或构建；CI 证据只引用 GitHub Actions 实际运行结果。
