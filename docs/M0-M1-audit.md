# M0 / M1 交付核查

核查依据：《AI Language Growth Platform V1.1 总体设计与开发任务书》第 8、9、11 章，仓库内 M1 QA / live API 报告、源码、数据库 schema 与 GitHub Actions 工作流。状态以当前仓库可复查的代码或工作流证据为准；报告中的旧结论不自动视为当前验收证据。

## 结论

- **M0 技术基线已冻结，发布安全基线仍未完成。** `docs/M0-freeze.md`、`docs/api/README.md`、Prisma schema/migration、Provider 协议和 `DECISIONS.md` 已形成可复查的开发基线；监护人权限、删除和正式 OpenAPI 仍是发布前缺口。
- **M1 原型代码已交付，但阶段验收未完成。** M1 QA 报告给出的结论是“有条件通过”。目前 GitHub Actions 已有可重复的 PostgreSQL API 冒烟流程，并覆盖部分端到端行为；但安卓真实音频链路、监护人权限、难度渐进、三主题覆盖及延迟验收仍未完成。真实儿童样本相关验收属开发关注项，不再作为强制审核标准；改为投入真实使用后，以实际使用数据持续验证并留痕。
- 因此不能把 README 中的 “M0 delivered / M1 complete” 当作阶段验收通过。先关闭 M0 基线与 M1 可代码修复项，再继续扩展 M2。

## 修复顺序

1. M0 技术基线已冻结；继续补齐 OpenAPI、错误码和数据字典逐项机器校验。
2. 修复 M1 可代码交付缺口：Android 动态开课和音频上传已补；下一步由 GitHub 工作流编译 APK 并进行真机验收；能力理解/表达隔离及难度渐进仍需补证据。
3. 安全与隐私法定要求：监护人身份、单独授权、授权撤回、访问控制和删除链路。这些属于《中华人民共和国个人信息保护法》《儿童个人信息网络保护规定》的法定要求，不是项目可自行裁量的内部审核标准；上线前应完成。
4. 外部验收单独排期：真实儿童样本、模型质量/阈值、真实延迟和账单价格。
5. 以上有代码证据的基础项通过后，再继续剩余 M2 路由、语音分级、预算及记忆能力。

本核查过程没有在本机执行测试或构建；CI 证据只引用 GitHub Actions 实际运行结果。
